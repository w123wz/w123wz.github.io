项目介绍

AI心理健康助手是一个基于 Spring Boot 3+Spring AI+Vue 3 构建的面向高校及青年的心理健康智能平台。系统打通了 SSE 流式心理疏导、文档驱动的 RAG 智能出题阅卷、异步情绪监控预警与多维数据可视化的全业务链路。采用前后端分离与双端鉴权架构，结合多级容灾降级与上下文状态缓存机制，实现了高可用、低延迟的生成式 AI 交互落地。

技术栈

前端：

  • 核心框架层
    Vue 3、Vite、Vue Router、Pinia
  • UI组件库
    Element Plus、@element-plus/icons-vue
  • HTTP & 网络层
    Axios、@microsoft/fetch-event-source
  • 图表 & 数据可视化
    ECharts 6
  • 富文本编辑
    @wangeditor/editor、@wangeditor/editor-for-vue
  • 样式处理
    Sass
  • 构建配置层
    Vite 配置文件、rolldown

后端：

  • Spring AI 1.0.0-M1
  • Spring Boot 3.2.5
  • Java 17
  • AI 模型：DeepSeek-V3.2（通过 SiliconFlow 代理，配置在 application.yml）
  • 数据库：MySQL + MyBatis-Plus 3.5.12
  • 存储：MinIO，对象存储，分两个 bucket：
    • mental-images - 存储用户上传的图片
    • mental-documents - 存储用户上传的文档
  • 认证：
    • Spring Security
    • JWT（Auth0 java-jwt）
  • SSE 流式输出：Reactor Flux + ServerSentEvent
  • 文档解析：PDFBox（PDF）、Apache POI（.doc/.docx）

流式 AI 对话（核心亮点）

路径：POST /stream，返回类型是 TEXT_EVENT_STREAM（Server-Sent Events）

完整流程：

  1. 用户发送消息 → 后端通过 ChatClient（Spring AI）调用 DeepSeek-V3.2
  2. 内存聊天记忆：使用 InMemoryChatMemory + MessageChatMemoryAdvisor，同一个会话会自动加载历史上下文（ensureMemoryLoaded 方法，最多加载最近 20 条）
  3. SSE 实时输出：每收到一段 AI 回复片段就推送给前端，事件类型为 message，全部完成后推 done 事件
  4. 异步情绪分析：每次对话后都触发 analyzeEmotionAsync（用 @Async("emotionAnalysisExecutor")）
  5. 消息持久化：用户消息和 AI 回复都存到 ConsultationMessage 表

System Prompt（定义在 PromptManage.java）：

  • 角色：专业、温暖、有同理心的 AI 心理健康助手，专门为大学生提供心理支持
  • 特点：善倾听、不急于给建议、共情优先
  • 危机干预：检测到高风险倾向时优先表达关心，鼓励寻求专业帮助

AI 情绪分析

触发时机：每次用户发送消息后，异步后台执行
获取接口：GET /session/{sessionId}/emotion

分析内容（通过 AI Prompt 要求返回 JSON）：

降级兜底机制：

  • 如果 AI 调用超时 / 失败 → 关键词匹配降级
    • 维护了正 / 负面关键词库（如 “难过、焦虑、轻生” 等 40+ 个关键词）
    • 匹配到高风险关键词时 riskLevel=4，触发危机提示
  • 如果缓存未命中 → 返回 null，让前端稍后重试（因为是异步分析）

AI智能出题考试模块

Controller: controller/ExamController.java

Service 层分工：

  • ExamGenerateService — AI 出卷（基于 RAG 理念）
  • ExamAiGradingService — AI 批改主观题
  • ExamService — 答题 + 提交 + 查看记录
  • ExamPaperAdminService — 试卷管理（发布/下线/删除）
  • ExamPaperPersistenceService — 试卷题目持久化

AI 自动出题（POST /api/exam/paper/generate）

完整流程：

  1. RAG 资料提取：从 MinIO 中下载用户指定的文档（PDF/DOC/DOCX/TXT/MD），用 DocumentContentExtractor 提取文本内容
    • 单文件上限 8000 字，总上限 20000 字
    • 保留原始文件名作为”资料来源”标识
  2. AI 生成 10 道题（Prompt 写死了严格规则）：
  1. 严格校验生成结果：
    • 题目数量必须是 10
    • 题型顺序必须符合 [1,1,1,1,2,2,2,3,3,4]
    • 总分必须是 100（AI 生成不对就按比例修正分数）
    • AI 失败自动重试 3 次（指数退避：3s → 6s → 12s）
  2. 入库：试卷 + 题目 + 试卷 - 文档关联表

考试答题流程

功能 路径 说明

注意：
这里的考试时间默认是25分钟，当时测试的时候用的是45分钟，已修改。当用户在考试时间内没有完成考试，会自动提交。用户手动提交的时候，会触发表单校验必须答完所有题，而系统自动提交的时候会跳过表单校验直接提交。

客观题（单选/多选/判断）：Java 代码直接比对答案，不经过 AI。
主观题/案例题（type=4）：
AI 评分维度（权重写在 System Prompt 里）：

AI 每道题返回：

  • score：0-100 得分率
  • comment：具体评语（50-150 字）
  • keyPointsHit：命中的参考答案要点
  • diagnosis：综合诊断建议

AI 综合评价（整套试卷）：

  • overallComment：整体评价（80-200 字）
  • strengths / weaknesses：优势 / 不足
  • suggestions：学习建议
  • riskLevel：0-4 风险等级

容错兜底：AI 评分失败时，主观题暂时记 0 分。

系统架构亮点总结

AI能力全景

AI场景 调用方式 降级策略
心理疏导对话 流式 ChatClient + ChatMemory AI不可用时对话失败（无降级）
情绪分析 ChatModel.call（非流式） 关键词匹配降级（40+正负面词库）
AI出卷 ChatModel.call 3次重试（指数退避），全部失败抛异常
主观题批改 ChatModel.call 3次重试，失败降级为0分
综合评价 ChatModel.call 失败返回 null，不影响主流程

RAG架构

目前阶段：朴素 RAG（Naive RAG）——直接把多份文档全文拼接（限2万字）塞给 AI 生成试卷。
预留了向量化字段：rag_status、chunk_count，说明后续可能接入向量数据库（Milvus/Pinecone 等）做真正的语义检索。

安全性

  • JWT 认证（Auth0 java-jwt，有效期 24h，刷新 token 7d）
  • Spring Security 过滤链 + 自定义 JwtAuthenticationFilter
  • Token 黑名单机制（退出登录后 token 立即失效）
  • BCrypt 密码加密
  • CORS 全局配置
  • 路径权限区分（公开路径 vs 需要认证）
  • 401/403 自定义响应

异步能力

  • 自定义 emotionAnalysisExecutor 线程池（AsyncConfig）
  • 情绪分析每次对话后异步执行，不阻塞主对话流程

数据库表（共12张）

user、consultation_session、consultation_message、emotion_diary、exam_paper、exam_question、exam_record、exam_paper_document、document、knowledge_article、knowledge_category、sys_file_info
